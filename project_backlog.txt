Phase 2: Data Validation & Pipeline (Offline Layer)
Goal: Build a robust, offline data ingestion engine using Pydantic before touching the browser.

TASK-2.1: Pydantic Schema & Sanitization Engine
* Priority & Complexity: High / Medium
* Objective: Define strict validation models for incoming data rows, handling multiple export formats and securing PII.
* Technical Details: 
   * Normalize input headers dynamically to support various export formats (e.g., "Date of Service" -> "Date", "A/I/O" -> "Role").
   * Concatenated Parsing: Support RIS export models by utilizing Regex to extract NHI, DOB, and Sex from combined "Patient" strings.
   * Explicitly strip "Patient Name" during initial parsing to ensure PII is never written to error or duplicate logs.
   * Validate NHI numbers using ^[A-Z]{3}(\d{4}|\d{2}[A-Z]{2})$.
   * Accept DD/MM/YY or DD/MM/YYYY date formatting, standardizing to DD/MM/YY and stripping time artifacts (e.g., 10:15).
   * Handle dirty A/I/O data (coerce "Assisted" -> "A"). Explicitly reject unresolvable conflicts (e.g., "A, I").
* DoD: Valid rows pass. Rows with unresolvable A/I/O conflicts or bad NHI/Dates are caught and written to validation_errors.csv without crashing the main script. PII is confirmed completely absent from all logs.
