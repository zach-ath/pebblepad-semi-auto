# **P3A: PebblePad Python Playwright Automation**

**Operational Runbook & Architecture Guide**

## **1\. Project Directory Structure**

Before executing the script, your project directory should look exactly like this:  
P3A\_Project/  
│  
├── inputs/                          \# MUST BE CREATED MANUALLY OR VIA SETUP  
│   └── data.csv                     \# Your raw export (e.g., Zac's dataset)  
│  
├── outputs/                         \# Auto-generated by the script  
│   ├── internal\_database.csv        \# Log of successfully saved records  
│   ├── validation\_errors.csv        \# Rows with bad Dates, NHIs, or A/I/O conflicts  
│   ├── duplicates\_skipped.csv       \# Rows already present in the internal\_database  
│   ├── uncategorised-examinations.csv \# Rows that failed to match regex rules  
│   └── Workbook\_log\_pages.csv       \# Cached URLs mapped from the Angular DOM  
│  
├── pipeline.py                      \# Offline Pydantic Validation & Regex Engine  
├── pebble\_engine.py                 \# Playwright Browser & Angular Interaction Layer  
├── pebble\_filler.py                 \# Main CLI Entry Point  
├── regex\_rules.json                 \# User-defined keyword mapping configuration  
├── requirements.txt                 \# Project dependencies  
└── .gitignore                       \# Ensures PII/CSVs aren't pushed to source control

## **2\. Installation & Setup (GitHub Quickstart)**

To run this pipeline flawlessly on a local machine, you must configure a Python Virtual Environment (venv) to prevent dependency conflicts.  
**Prerequisites:** Ensure you have Python 3.10+ and Git installed.  
**Step 1: Clone the Repository & Enter the Directory**  
git clone \<your-github-repo-url\>  
cd P3A\_Project

**Step 2: Create the Virtual Environment** Run the following command to create an isolated Python environment named venv:  
python \-m venv venv

**Step 3: Activate the Virtual Environment** You must activate the environment every time you open a new terminal to run the script.

> * **Windows (Command Prompt):** venv\\Scripts\\activate.bat  
> * **Windows (PowerShell):** venv\\Scripts\\Activate.ps1  
> * **macOS / Linux:** source venv/bin/activate *(You will know it worked if you see (venv) at the beginning of your terminal prompt).*

**Step 4: Install Dependencies & Browser Binaries** With the venv active, install the required Python packages, and then instruct Playwright to download the Chromium browser engine it needs to run:  
pip install \-r requirements.txt  
playwright install chromium
You need Google Chrome for this to work, but you can install that manually.

**Step 5: Scaffolding Data Directories** Ensure your local inputs/ and outputs/ folders exist. (Git usually ignores empty folders, so you may need to create them). Place your raw clinical export inside the inputs/ folder and name it data.csv.

## **3\. The Core Code Modules**

### **A. pipeline.py (The Offline Engine)**

This file processes the data *before* a browser ever opens.

> * **Header Normalization:** It dynamically reads headers, meaning it accepts both Date of Service (Zac's dataset) and Date.  
> * **PII Stripping:** It intentionally ignores the Patient Name column. Patient details are immediately dropped from memory and will never be written to your error logs.  
> * **Pydantic Validation:** Strict enforcement of NHI formatting, Date formatting (auto-converting 4-digit years to 2-digit years), and A/I/O matrix conflict resolution.  
> * **Regex Routing:** It searches the regex\_rules.json to assign a target PebblePad Page and Table to each valid row.

### **B. pebble\_engine.py (The Browser Engine)**

This file handles the Playwright automation.

> * **DOM Navigation Mapping:** Instead of brittle clicking, it parses PebblePad's item-data JSON attribute to map the workbook structure and caches the absolute URLs.  
> * **Scoping:** It targets specific tables on a page using section\[aria-label="..."\].  
> * **Event Dispatching:** Bypasses Angular's "typing" block by forcefully triggering JS input, change, and blur events on the text cells.  
> * **Isolate Scope Hack:** Uses page.evaluate() to hook into Angular 1.x's isolate scope, directly injecting JavaScript Date objects into the stubborn \<table-cell-datepicker\> controllers.

### **C. pebble\_filler.py (The CLI)**

The main controller. It uses argparse to give you terminal commands to control the pipeline securely.

## **4\. Step-by-Step Execution Guide**

### **Step 1: Preparation**

> 1. Ensure your virtual environment is **active** (look for the (venv) prompt).  
> 2. Place your raw clinical export into `inputs/data.csv`.  
> 3. Update `regex_rules.json` if you have new examination types you want to automatically route. This looks at the "examination type" for keywords for sorting, but does not categorize paediatric cases.
Your data should have the following information.

| Patient | Services | Serviced | Clinical Indications | A/I/O |
| :--- | :--- | :---: | :--- | ---: |
| Claus, Santa Male 01/01/1996 ABC1234 | Xray Right Foot | 10/10/2026 | sprained ankle | A |

### **Step 2: The Dry-Run (Testing Phase)**

Always run a dry-run first to catch categorization or formatting errors. **Command:**  
python pebble\_filler.py \--test

**What happens:**

> 1. pipeline.py reads data.csv.  
> 2. It strips patient names, checks for duplicates against outputs/internal\_database.csv, validates formatting, and applies your regex rules.  
> 3. It writes failed rows to outputs/validation\_errors.csv and outputs/uncategorised-examinations.csv.  
> 4. It prints a terminal summary (e.g., "Total rows ready for injection: 45") and exits *without* launching the browser.

### **Step 3: Full Execution & Authentication**

Once you are happy with the dry-run summary, run the full script. **Command:**  
python pebble\_filler.py

*(Note: If the PebblePad workbook structure has changed, or it's your first run, add the \--remap flag to force the script to rebuild the URL cache: python pebble\_filler.py \--remap)*  
**What happens:**

> 1. The script runs the offline pipeline instantly.  
> 2. A headed Chromium browser launches and navigates to the PebblePad login screen.  
> 3. **The Terminal Pauses.** It will say: ⏸ AUTOMATION PAUSED.  
> 4. **Manual Action:** You log in via your SSO, do your 2FA, and manually click into your specific Clinical Logbook Workbook.  
> 5. Once the workbook's main dashboard loads, you hit ENTER in your terminal.

### **Step 4: Auto-Injection (The Engine Takes Over)**

**What happens:**

> 1. **Caching:** Playwright scans the Angular DOM, extracts the JSON tree, resolves all the template links, and caches them to Workbook\_log\_pages.csv.  
> 2. **Navigation:** It groups your data by Target Page to minimize page loads. It navigates to the first target page (e.g., "Appendicular skeleton").  
> 3. **Targeting:** It looks for the specific table (e.g., "Upper limb excluding the shoulder") and locates the *last* empty row.  
> 4. **Injection:**  
   * It fires the Isolate Scope hack to inject the Date.  
   * It dispatches native JS events to inject the NHI, Exam Type, and Indications.  
   * It clicks the correct A, I, or O radio button.  
> 5. **Mutation Waiting:** The script pauses, watching the DOM until Angular registers the data and automatically generates the *next* blank row.  
> 6. **Saving:** Once a table is complete, it clicks the PebblePad "Save" button, waits 5 seconds for background syncing, and appends the successful rows to your local internal\_database.csv.  
> 7. **Reporting:** The browser closes, and a final summary report is printed to your terminal.
